# Power Desk Delivery Quality Scorecard

Use this scorecard to evaluate whether the delivery system is working consistently for new hires and current developers.

| Dimension | Minimum operating standard | Strong team outcome | Evidence |
|---|---|---|---|
| Standard use | Required lifecycle stages and controls are followed | The same versioned standard is reused across solutions | Release history and solution records |
| Reusable patterns | Approved templates and skills are used where applicable | Common work is completed through maintained, reusable patterns | Skill registry and usage records |
| Efficiency | Comparable work is measured with defined start and stop points | Repeatable activities show sustained improvement without reducing quality | Baseline and outcome data |
| Quality | Required QA is completed before release | No open critical defects and critical regression paths pass | Test reports |
| Traceability | Requirements map to acceptance criteria | Acceptance criteria map to tests and retained evidence | Traceability matrix |
| Developer enablement | Developers can locate and follow the correct process | A new or current developer completes work without relying on undocumented knowledge | Onboarding exercise and feedback |
| Governance | Security, records, licensing, rollback, support, and ownership are recorded | Decisions are consistent and reviewable across solutions | Gate checklists |
| Handoff | Documentation and named support ownership exist | A successor can execute regression and support tasks | Walkthrough and acceptance record |

## Measurement rules

- Record a baseline before introducing automation or a new reusable pattern.
- Compare like-for-like work using the same start and stop definitions.
- Report sample size, median, range, exclusions, and data source.
- Separate AI generation time, human review time, rework, and waiting time.
- Never represent projected savings as realized savings.
- Use team and solution outcomes to guide continuous process improvement.
