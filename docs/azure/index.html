The Azure gate

Three checks before the first write.

If one check is missing or mismatched, stop and report the blocker.

01

Confirm the approved scope

Name the workload, environment, approval reference, allowed locations, and exact resource group.

02

Verify the executing identity

Confirm the actual identity and subscription used by the CLI, MCP, SDK, or workflow—not an assumed default.

03 ✓

Review the operation

Validate every target, permission, location, cost implication, and rollback before an approved write.

Stop conditions

Do not guess your way into Azure.

An Owner login, CLI default, existing resource group, or successful sign-in does not prove that a workload is authorized.

  • No explicitly approved workload resource group
  • Identity or subscription cannot be verified
  • Target, region, permission, data use, or cost is outside the approved boundary
  • The plan includes deletion, public exposure, retention, or access changes without separate approval
