Quick start 01

Review the CSM handoff

Use this after qualification, discovery, human refinement, and Product Owner acceptance place an approved discovery package in the SharePoint project folder.

About 20 min
  1. 1 Confirm the handoff package Verify the folder contains the charter, scope, Product Owner-accepted specification, attributed transcript reference, owner, and known constraints.
  2. 2 Trace transcript to specification Confirm every client-specific statement is attributable, unsupported wording was removed, and assumptions and open questions remain visible.
  3. 3 Verify discovery controls Recording and transcription must use approved tools with required consent and policy, controlled access and retention, and an approved AI processing boundary.
  4. 4 Copy the SharePoint folder link Use the approved project folder—not an individual document or a local download.
  5. 5 Launch the intake agent Provide the folder link so the agent can normalize requirements, identify gaps, and recommend the delivery path.
  6. 6 Decide readiness before architecture Confirm IDs, criteria, risks, and unknowns; assign Ready, Discovery, or Re-scope. Ready plus accountable developer approval opens architecture—not build or release.

Practice objective

Transcript → story → intake

Use only fictional content: Request owner: “A requester needs missing required information identified before submission.” Draft a requester story and a Given/When/Then criterion, then carry the data source, permissions, records, volume, and support details into intake as unknowns. Simulated Product Owner acceptance confirms the specification wording only; readiness and architecture remain separate gates.

Quick start 03

Validate and release

Use this path when the solution is ready for independent review.

Before every release
  1. 01 Confirm the exact test target Record the published version, environment, persona, synthetic fixture, and allowed mutations. Power Apps live QA ↗
  2. 02 Run deterministic checks first Collect platform checker, accessibility, configuration, and traceability results. Check interfaces ↗
  3. 03 Test the live requirement Record expected, actual, persona, data, and breakpoint results in the published surface. Use test case template ↗
  4. 04 Capture and classify evidence Keep pass, fail, blocked, and review-needed results visible; never infer a pass. Evidence guide ↗
  5. 05 Pass the release gate Resolve defects, blocked paths, risks, rollback, support, and approval items. Release checklist ↗
  6. 06 Transfer ownership Provide support context and known limitations. Handoff checklist ↗
