# Skill Priority Register

This sequence is derived from recurring portfolio patterns and evidence gaps. Detailed source citations remain in the internal evidence store.

| Rank | Candidate skill | Primary benefit | Prerequisite |
|---|---|---|---|
| 1 | Successor-ready solution record generator and validator | Closes ownership, dependency, connection, control, runbook, and handoff gaps | Approved handoff schema |
| 2 | SharePoint and Power Automate workflow scaffold | Standardizes common list/library/page and automation foundations | Platform standards |
| 3 | Intake-to-SharePoint pattern | Reuses validation, attachments, mapping, confirmation, and notification | Approved intake tools |
| 4 | Approval, audit-evidence, and document-export pattern | Standardizes routing, reassignment, comments, evidence, completion, and escalation | Records/security decisions |
| 5 | Product-family tenantization skill | Separates reusable logic from implementation-specific configuration | Product-family baseline |
| 6 | Persona and dual-layer permission validator | Verifies application and data-layer access with least privilege | Test identities |
| 7 | Defect, UAT, release, and rollback skill | Standardizes classification, testing, deployment, rollback, retest, and acceptance | Release model |
| 8 | External integration wrapper and secret-safe handoff | Standardizes authentication boundaries, retry, idempotency, licensing, and support | Approved secret boundary |
| 9 | Playwright and visual evidence runner | Automates stable journeys and evidence while retaining human release authority | Deterministic QA baseline |
| 10 | AI-assisted change reviewer and estimation comparator | Requires plan, impact, validation, and explicit separation of estimates from actuals | Measured baseline |

## Promotion criteria

A candidate becomes an approved reusable skill only when:

- inputs and preconditions are explicit
- human approvals and prohibited actions are explicit
- output has a stable schema
- failure and uncertainty are surfaced
- deterministic validation exists where applicable
- a second developer completes a controlled example
- source, version, and retrospective evidence are retained
